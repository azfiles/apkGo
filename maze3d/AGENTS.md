# Godot、资源目录与数据关卡

先读 [仓库约定](../AGENTS.md) 和 [建模规范](../docs/maze3d/MODELING.md)。本文件适用于 `maze3d/` 下的游戏、资产、关卡和测试。

## 分层与兼容

- `assets/model_catalog.json` 维护资源 ID、GLB 路径、Blender 源文件、`source_root` 和简化碰撞盒。更换美术时保留逻辑 ID；新增模型应同时交付可编辑源文件。
- `asset_library.gd` 负责校验、缓存和实例化；`level_data.gd` 负责关卡数据校验；`maze.gd` 负责坐标、寻路与安全位置；`world.gd` 负责通用场景组合与物理。作者指定的模块摆放进入 JSON `scenery`。
- Godot 可继续生成通用碰撞、特效、辅助几何和合批实例；新的主要美术模块沿用 Blender/GLB 资源库。
- 章节数量、标题和路径来自 `levels/index.json`，星星数量来自各章 `motes`，避免在界面、流程或存档中写死当前四章与各章星数。
- 保持稳定 `level_id`，兼容旧数字 `chapter`。已发布章节的布局、出生点、目标与挑战坐标、灯塔和星星数组顺序属于兼容数据；确需调整时同步处理旧存档并更新回归依据。
- 数据结构不兼容变更需明确版本和迁移；同步校验器、消费者、导出与测试，不静默改变 `version: 1` 的含义。无效数据应在替换运行世界前被拒绝。
- 布朗继续使用 `character.gd` 驱动的 14 个刚性动作节点及四组表情几何，保留节点名、层级、枢轴和厚度。具体节点以资源目录、`character.gd` 和源文件约定为准。

## 复杂场景与物理

- 新章节使用模块化 GLB、网格、`scenery`、`regions` 与 `environment` 扩展。通路和场景摆放分别描述，关卡不依赖 Blender 内部整场景布局。
- JSON 网格格点为 `[x,z]`，一格 4 米；`scenery.position` 为 Godot 世界 `[x,y,z]`，`rotation_y` 为角度，`scale` 为正统一缩放且不超过当前校验器上限 4。
- `#` 为墙、`.` 为地面、`~` 为无支撑水面、`=` 为带真实支撑和护栏的桥。当前是单层通路加局部跳跃，高架引水渠是景观。
- 多层可行走世界需要同步扩展寻路、落脚点、碰撞和存档高度。模型抬高或景观增加不能作为多层玩法已经实现的证据。
- 简化碰撞盒与视觉模型对齐，跟随摆放旋转和缩放；避免把装饰网格全部变为三角网格碰撞。实际走过拱门、桥头、沿岸和出口，确认柱子、护栏与门框不堵路。
- 保持挑战两侧安全落脚点；当前石栏高度上限 0.75 米、缺口跨度上限 1.4 米，挑战不覆盖目标。修改该能力边界时同步角色物理、校验与验证。
- 保留移动端 Compatibility 渲染、资源缓存与静态合批；碰撞和关键交互不随画质开关失效。

## 验证与资源交付

- 修改游戏、GLB、目录或关卡后，从仓库根运行 `bash scripts/maze3d/test.sh`。新增章节应纳入数据检查与连续物理通关，不能只检查 JSON 连通或传送后拍图。
- 模型和场景改动在 Godot 中实际渲染，检查比例、材质、方向、遮挡与碰撞；角色还需正、侧、背面及跑跳表情审阅。
- 新增中文界面或关卡文字后运行 `python3 scripts/maze3d/prepare_assets.py` 更新字体子集；核对生成差异。
- Android/Linux 导出保持 JSON 显式包含及 `all_resources`，动态目录引用的 GLB 必须进入成品。改动资源打包时运行 `build.sh` 的成品资源包验证。
- FPS 使用 `Engine.get_frames_per_second()`，保持 0.5 秒刷新、触控穿透、暂停菜单开关和偏好持久化；保留冷启动恢复覆盖。
